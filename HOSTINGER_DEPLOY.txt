Hostinger GIT：fatal: Need to specify how to reconcile divergent branches
================================================================================

原因：服务器上的克隆里有过提交 / 合并，和 GitHub 的 main 分叉了；
      Hostinger 点 Deploy 时会执行 git pull，新版 Git 必须先配置 pull 策略。


--------------------------------------------------------------------------------
方式 0（强烈建议）—— 不用 Hostinger GIT：GitHub Actions + FTP 自动上传
--------------------------------------------------------------------------------

仓库已包含：.github/workflows/deploy-hostinger-ftp.yml

推送 main 后由 GitHub 构建前端并 FTP 上传整站（排除 node_modules / .git），不再依赖
Hostinger 面板里的「GIT Deploy」，可从根源避开 divergent branches。

1) GitHub → 本仓库 → Settings → Secrets and variables → Actions

   New repository secret（三个必填）：
   HOSTINGER_FTP_HOST      （hPanel → FTP 里主机名，多为 ftp.hostinger.com）
   HOSTINGER_FTP_USER
   HOSTINGER_FTP_PASSWORD

   可选：Repository variable（仅当 FTP 根目录下路径不是 public_html/frontend/dist/ 时）：
   HOSTINGER_FTP_SERVER_DIR   例如 domains/你的域名/public_html/frontend/dist/
   （必须以 / 结尾；留空则默认上传为 frontend/dist/，即假设 FTP 登录根就是 public_html）

2) 推送任意提交到 main，或 Actions → Deploy Hostinger (FTP) → Run workflow。

3) hPanel → GIT：建议关掉该站的 Auto Deployment，避免 GIT 与 FTP 两套部署互相覆盖。

Workflow 默认已使用明文 FTP（protocol: ftp），GitHub → Hostinger 一般比 FTPS 稳定。
若坚持 FTPS：在仓库 Variables 设置 HOSTINGER_FTP_PROTOCOL = ftps（必要时对照 hPanel 的 TLS 端口）。
仍失败请打开 Actions → 失败的任务 → Deploy 步骤日志，常见原因：HOSTINGER_FTP_HOST 错误（应用 hPanel「FTP
帐户」显示的主机名）、用户名含后缀、密码含特殊字符、或 HOSTINGER_FTP_SERVER_DIR 与 FTP 根目录不符。

完成后无需再点 Hostinger 的 GIT Deploy。

方式 A —— 开 SSH，修好面板里的 git pull
--------------------------------------------------------------------------------

1) hPanel → Advanced → SSH Access → 打开 SSH，用面板给的账号密码登录。

2) 先设全局策略（只要做一次，以后 Deploy 都会用 merge）：

   git config --global pull.rebase false

3) 进入 Hostinger 部署用的目录（里面必须有 .git）。路径因套餐而异，常见：

   cd ~/domains/你的域名/public_html

   若不确定，在 SSH 里搜：

   find ~ -maxdepth 8 -name ".git" -type d 2>/dev/null

   看到含 count168test 或 public_html 的路径，cd 进去。

4) 强制让服务器和 GitHub main 完全一致（丢掉「只在服务器上」的提交）：

   git fetch origin
   git reset --hard origin/main

5) 回到 hPanel → GIT → 再点 Deploy。


--------------------------------------------------------------------------------
方式 B（没有 SSH 或不想登终端）—— 删掉旧克隆，重新连仓库
--------------------------------------------------------------------------------

警告：会删除当前部署目录里的 Git 历史；请先备份网站文件 / 数据库。

1) hPanel → Websites → 你的网站 → GIT → 若有 Remove / Disconnect / Delete，
   先断开当前仓库与网站的关联（具体按钮名以面板为准）。

2) File Manager → 打开 GIT 当时选的「安装路径」（例如 public_html 或子目录）。

3) 删除该目录下隐藏的 .git 文件夹，以及你需要替换的旧文件（或整个清空该目录，
   若整站都由 Git 部署且你已备份）。

4) hPanel → GIT → 重新 Add repository：
   - Repository：https://github.com/kunzzgroups/count168test.git
   - Branch：main
   - Install path：与网站文档根一致的路径

5) 第一次 Deploy 会全新 clone，一般不会再出现 divergent（除非以后又在服务器上改代码）。


--------------------------------------------------------------------------------
方式 B2（无 SSH）—— 只改仓库里的 .git/config（很多面板可用）
--------------------------------------------------------------------------------

1) File Manager → 打开部署目录 → 打开「显示隐藏文件」。

2) 进入 .git 文件夹，编辑 config 文本文件。

3) 在文件末尾增加（若已有 [pull] 段则只补 rebase 行）：

   [pull]
       rebase = false

4) 保存后回到 GIT → 再点 Deploy。

说明：这等价于在该目录执行 git config pull.rebase false；Deploy 进程读同一仓库时会生效。


--------------------------------------------------------------------------------
方式 C（仍失败时检查）
--------------------------------------------------------------------------------

- Deploy 用的 GitHub 仓库必须是：kunzzgroups/count168test（和本地 remote 一致）。
- 若方式 A 用了 --global 仍失败：Deploy 可能用别的系统用户跑 git。请在「部署目录」
  执行本地配置（或改用方式 B2）：

  cd /部署目录
  git config pull.rebase false
  git fetch origin && git reset --hard origin/main
